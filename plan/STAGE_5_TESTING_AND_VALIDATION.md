# Stage 5: End-to-End Testing, Security Hardening & Validation

## 1. Цели и назначение этапа

Цель финального пятого этапа — провести комплексное тестирование всех компонентов системы (Rust ядро, криптографический рэтчет, Node.js MCP мост, стелс-браузер, Tor, файрвол и генератор SARIF) и верифицировать сценарии реального использования плагина.

---

## 2. Матрица тестовых сценариев

### Сценарий 1: Криптографический барьер и защита от обратной атаки (Ratchet & Pivot Defense)
* **Тест 1.1 (Валидная подпись):** Запрос от хоста, подписанный `Host_Priv`, успешно проходит верификацию в Rust `RatchetGuard` и выполняется.
* **Тест 1.2 (Неподписанный запрос):** Прямой HTTP-запрос к порту 9999 песочницы без `X-Signature-Host` отклоняется с кодом `401 Unauthorized`.
* **Тест 1.3 (Протухший токен / Replay Attack):** Повторная отправка запроса со старым сессионным токеном через 35 секунд отклоняется с `401 TokenExpired`.
* **Тест 1.4 (Затирание памяти `zeroize`):** Проверка сброса буферов сессионных ключей в Rust демоне после ротации.
* **Тест 1.5 (Zero-Trust Ingress Barrier):** Проверка невозможности отправить исходящий RPC-запрос из контейнера на хост.

### Сценарий 2: Локальный аудит репозитория (`local_codebase`)
* **Тест 2.1:** Запуск `sandbox_set_scope({ mode: "local" })`.
* **Тест 2.2:** Проверка правил `nftables` — внешняя сеть полностью заблокирована (`default drop`).
* **Тест 2.3:** Запуск Semgrep/AST-grep через `sandbox_exec`, поиск секретов и уязвимостей в кодовой базе.
* **Тест 2.4:** Генерация отчета `audit-report.sarif` и проверка его соответствия спецификации SARIF v2.1.0.

### Сценарий 3: Удаленный DAST-аудит (`remote_url`) + Стелс-браузер + Decoy шум
* **Тест 3.1:** Запуск `sandbox_set_scope({ mode: "remote", targets: ["https://example.com"] })`.
* **Тест 3.2:** Проверка `nftables` — трафик разрешен строго на IP-адреса `example.com`.
* **Тест 3.3:** Запуск стелс-сессии `sandbox_browser_audit` с кривыми Безье (`ghost-cursor`), сбор DOM-дерева, куки и заголовков.
* **Тест 3.4:** Проверка генерации фонового шума (`decoy_traffic.js`).
* **Тест 3.5:** Извлечение JS-бандлов и Source Maps через `sandbox_bundle_extract` (Rust `rquest`).
* **Тест 3.6:** Точечная проверка L7 IP Spoofing (`X-Forwarded-For: 127.0.0.1`) через `sandbox_http_probe`.

### Сценарий 4: Маршрутизация через Tor и динамическая ротация IP
* **Тест 4.1:** Запуск `sandbox_set_scope({ proxy: "tor" })`.
* **Тест 4.2:** Проверка исходящего IP-адреса через Tor SOCKS5h (`127.0.0.1:9050`).
* **Тест 4.3:** Вызов `sandbox_rotate_tor_ip` (`SIGNAL NEWNYM`).
* **Тест 4.4:** Проверка получения нового IP-адреса и новой цепочки узлов.
* **Тест 4.5:** Проверка отсутствия DNS/WebRTC утечек.

### Сценарий 5: Ловушки Deception и аварийные процедуры (Canary & Panic)
* **Тест 5.1:** Попытка чтения фиктивного файла `/root/.aws/credentials` внутри контейнера.
* **Тест 5.2:** Проверка срабатывания Linux `inotify` watcher в Rust и моментального вызова `panic::kill_switch()`.
* **Тест 5.3:** Проверка полного глушения сети (`conntrack -F` + drop all).
* **Тест 5.4:** Вызов `sandbox_reset` — проверка удаления скомпрометированного контейнера и создания чистого за доли секунды.

### Сценарий 6: Watchdog и фоновые задачи (Output Cap & Background Jobs)
* **Тест 6.1:** Запуск команды, генерирующей 200 КБ вывода.
* **Тест 6.2:** Проверка усечения ответа до 30 000 символов для агента и сохранения полного дампа в `/workspace/logs/cmd_<id>.log`.
* **Тест 6.3:** Запуск длинной команды через `sandbox_start_background`, опрос инкрементальных логов через `sandbox_poll_logs`.

### Сценарий 7: Безопасность хоста (Host Jail & Redaction)
* **Тест 7.1:** Попытка чтения `sandbox_fs_read("../../.ssh/id_rsa")` — проверка отклонения с ошибкой `AccessDenied`.
* **Тест 7.2:** Проверка маскирования токенов (`Bearer s***123`) в SARIF-отчетах и логах.

3. [ ] Выполнить ручной прогон тестовых сценариев 1–7.
4. [ ] Сформировать финальный отчет о верификации в `walkthrough.md`.
